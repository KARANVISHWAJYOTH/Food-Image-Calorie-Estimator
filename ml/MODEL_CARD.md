# NutriVision AI Model Card

## Model details

| Field | Value |
| --- | --- |
| Name | `MultiTaskCNN` (ResNet-50 backbone) |
| Task | 101-class food classification + 4-target nutrition regression |
| Input | RGB image, resized/cropped to 224×224, ImageNet normalization |
| Outputs | `foodClass` logits (101), `[calories, protein, carbohydrates, fat]` |
| Parameters | ~24M (ImageNet-pretrained ResNet-50 plus two heads) |
| Runtime | PyTorch 2.x, CPU or CUDA; INT8 variant maps `nn.Linear` to qint8 |
| Checkpoint format | `state_dict`/`model_state_dict`, `class_names`, `target_stats`, `val_metrics`, optional `config`/`metadata` |

Regression targets are z-scored with training-split mean/std
(`target_stats`) and de-normalized at inference. Dietary fiber is derived
downstream from predicted carbohydrates and the predicted food category; it is
not a model output.

## Intended use

- Educational and portfolio demonstration of a multi-task food vision pipeline.
- Estimating the dominant dish and its approximate energy/macronutrients from a
  single, well-lit photo of one plate.

## Out of scope

- Medical, clinical, or dietary decisions.
- Multi-dish scenes, mixed plates, and partially eaten portions.
- Exact portion mass from a single monocular image; the model predicts the
  training-distribution average serving, not a per-photo portion.
- Sugar, sodium, potassium, micronutrients, and ingredient lists.

## Training data

- **Classes:** Food-101 (101 dish categories) via `ml/data/download_food101.py`.
- **Nutrition targets:** Nutrition5k annotations, aligned to Food-101 classes by
  fuzzy string matching with manual overrides (`ml/data/align_labels.py`).
  Nutrition5k provides calories, protein, carbohydrates, and fat; it does not
  measure dietary fiber.
- **Splits:** stratified 70/15/15 manifest generated by `ml/data/splits.py`.

## Training procedure

- Two stages in `ml/training/train.py`: frozen backbone with head-only training,
  then `layer4` plus heads at a lower learning rate.
- Loss: cross-entropy for classification plus Smooth L1 on z-scored nutrition
  targets (`ml/training/losses.py`), weighted by configurable `lambda_cls` and
  `lambda_reg`.
- AMP and gradient scaling when CUDA is available.
- Augmentation: random resized crop, horizontal flip, rotation, color jitter
  (`ml/preprocessing/transforms.py`); the cheap crop runs before the pixel-wise
  ops because rotating full-resolution photos dominated loader time.

## Serving checkpoint (trained 2026-11-17)

| Field | Value |
| --- | --- |
| Training data | Food-101, 70,700 train / 15,150 validation images (seed 42) |
| Schedule | 1 epoch frozen heads at lr 1e-3, then 3 epochs `layer4` + heads at lr 1e-4, cosine, batch 32, AMP fp16 |
| Validation top-1 | **78.9%** |
| Validation calories MAE | **48.2 kcal** |
| Validation protein / carbs / fat MAE | 4.0 g / 7.7 g / 3.3 g |
| Independent test top-1 / top-5 | 78.9% / 93.9% |
| Independent test calories MAE | 48.4 kcal (RMSE 67.3, R² 0.71) |
| File | `backend/app/best_model.pth` (embeds `class_names`, `target_stats`, `val_metrics`) |

**Label caveat.** Nutrition targets are per-class constants, not per-image
measurements: 7 classes use averages of matched Nutrition5k dish annotations and
94 use documented per-serving estimates (`ml/data/manual_overrides.yaml`). All
images of a class share the same target, so the regression MAE measures how
closely the model reproduced those class priors. The 78.9% top-1 figure is
evaluated against genuine per-image Food-101 labels.

## Evaluation

`ml/evaluation/evaluate.py` computes Top-1/Top-5 accuracy, macro precision/
recall/F1, and per-target MAE, RMSE, Pearson r, and R² on the held-out test
split, exporting JSON and Markdown.

Held-out validation metrics are stored in the checkpoint itself and are surfaced
by `GET /api/health` (`trainedMetrics` and `modelValidation.val_metrics`). The
independent test split was evaluated with `ml/evaluation/evaluate.py` (Top-1
78.9%, Top-5 93.9%, calorie MAE 48.4 kcal); `metrics.json`, the Markdown report,
and confusion-matrix/scatter plots are in `ml/evaluation/results/`. A fresh clone
without `backend/app/best_model.pth` gets `503` with specific rejection codes,
because the API always validates the checkpoint before serving.

Report accuracy, MAE, or confidence figures only when they come from a
checkpoint's `val_metrics` or from `ml/evaluation/evaluate.py`; never estimate
them by hand.

## Optimization artifacts

`ml/optimization` can prune convolutional filters, dynamically quantize Linear
layers, export TorchScript/ONNX, and benchmark latency. All pruned (20/30/50%)
and INT8 artifacts under `ml/optimization/` are derived from the installed
checkpoint and were re-evaluated on 1,504 held-out test images
(`ml/optimization/benchmark_results.md`):

- FP32 baseline: 77.9% top-1, 94.4% top-5, 49.0 kcal MAE, ~44.8 ms CPU / 8.3 ms GPU.
- Pruning at 20/30/50% keeps 75.1–76.2% top-1 with 49.8–51.6 kcal MAE.
- Dynamic INT8: 79.5% top-1, 47.9 kcal MAE, 91.7 MB (-4.7%).

The pruned and INT8 variants match FP32 latency within noise on this machine:
unstructured sparsity does not map to dense CPU kernels, and dynamic INT8 only
converts the small Linear head while convolutions stay FP32. Latency figures
describe the benchmark host only; accuracy figures come from the same held-out
split as the FP32 baseline.

## Limitations and risks

- Visual ambiguity between visually similar dishes is expected; confidence is
  the softmax top probability and can be miscalibrated.
- Nutrition labels come from a cafeteria dataset and may not generalize to
  home-cooked or regional cuisines.
- Portion size is inferred implicitly from the image and class-average stats;
  scale cues (utensils, hands) are not modeled explicitly.
- Uploaded images are stored server-side for history display; deployments should
  treat them as personal data and apply retention/access controls.

## Reproduction

1. Download Food-101 and Nutrition5k, then run the alignment and split scripts.
2. Train on a GPU (see `ml/training/RUN_INSTRUCTIONS.md`).
3. Verify the checkpoint with `ml/training/verify_checkpoint.py`.
4. Place it at `backend/app/best_model.pth` (or set `MODEL_WEIGHTS_PATH`) and
   confirm `GET /api/health` reports `modelValidation.valid: true`.
